# Wavemaker：从"海浪合成器"到"自然声场引擎"

> 起点：给抖音视频配乐时，DJ Osama 的《Artificial》配上一段海边看鸟的视频，
> 海浪冲刷沙滩的声音和画面完美契合。于是想做一个海浪发生器。

这份文档做三件事：把想法发散开、收敛出第一个该 build 的东西、列出目前被忽略的部分。

---

## 0. 先回答最核心的疑虑："合成的海浪不真实"

这个前提大概率是错的，而且它是整个项目的地基，所以放在最前面。

- 海浪声在物理上就是**被调制的宽带噪声**：远处的涌是低通噪声，拍岸是一次带通噪声的爆发，
  冲滩和回退是高频嘶声在时间和空间上的滑动。电影音效师做海浪，大量就是用滤波噪声叠层。
- 听起来"假"的合成海浪，问题几乎从不在波形，而在四件事：
  1. **包络**太规则（真实的浪每一次的上升、拍击、回退时长都不一样）
  2. **没有分层**（一个噪声源过一个滤波器，永远是"电视雪花"）
  3. **没有空间感**（真实的浪是从左到右或从右到左沿着海岸线跑的）
  4. **没有材质**（沙滩、卵石滩、礁石的声音差别比"浪大浪小"大得多）
- 仓库里的 `index.html` 就是为了验证这一点：纯 Web Audio 合成，零采样，
  分了 8 层（远涌床、涌、拍岸、冲滩、泡沫、卵石滚动、礁石低频、风）加海鸥。
  先听，再决定要不要引入真实采样。
- 如果最后 20% 的真实感确实需要采样，正确的做法不是"放一段循环录音"，
  而是**颗粒合成（granular）**：把真实录音切成几十毫秒的颗粒，由合成引擎的包络来驱动播放。
  这样既有真实质感，又保留了"参数可调、无限不重复"的核心优势。

结论：**合成不是退而求其次，它恰恰是这个产品能存在的理由。** 采样库和白噪音 app 做不到的，
合成都能做：无限不重复、参数实时可调、和画面对拍、离线、无版权问题、能塞进硬件。

## 1. 发散：这个想法能长成的五个方向

| 方向 | 一句话 | 用户是谁 | 现有对手 | 你的差异点 |
|---|---|---|---|---|
| A. 创作者音效工具 | 程序化海洋音效引擎，导出 WAV / 分轨 / 无缝循环 | 短视频、广告、影视、游戏的音频人 | 采样库（Splice、Boom）、Krotos、Le Sound AudioWind 类程序化插件 | 和画面对拍（tap-to-wave）、无限变体、免版权 |
| B. 陪伴 / 专注 / 睡眠 | "不循环的海" | 普通人 | Noisli、myNoise、Endel、Calm 里的白噪音 | 红海；只靠这个方向很难赢，但作为附带功能没问题 |
| C. 数据驱动的真实海滩 | 输入一个海滩，用**此刻真实的海况**（浪高、周期、风）驱动合成 | 想念某片海的人；旅行前的人；地理教育 | 几乎没有 | "现在青岛石老人的海是什么声音"，独一份的情感钩子 |
| D. 交互 / 生物信号 | 植物电信号、心率、呼吸来调制海浪 | 装置艺术、展览、疗愈空间 | PlantWave、MIDI Sprout（只出 MIDI 音符） | 把"植物的信号"翻译成"海的节奏"，比出钢琴声有意义得多 |
| E. 硬件 | 桌面上的一台海浪机器：旋钮、小喇叭、无屏幕 | 送礼、桌面摆件、模块合成器玩家 | Yogasleep 类白噪音机（循环采样）、Eurorack 噪声模块 | 里面跑的是真正的合成引擎，不是循环采样 |

这五个方向不是互斥的，它们共用同一个内核：**一个用参数描述"一片海"的程序化引擎**。
只要内核是参数化的，A 是导出功能，B 是长时播放，C 是把 API 数据映射成参数，
D 是把传感器数据映射成参数，E 是把引擎用 C++ 重写塞进单片机。

所以第一个要 build 的不是"某个 app"，而是**引擎 + 参数模型**。

## 2. 收敛：第一个版本 build 什么

### 2.1 核心：参数化的"海"

一片海用这些参数描述（这也是海洋气象学和 API 用的语言，方向 C 会直接受益）：

| 参数 | 含义 | 来源 |
|---|---|---|
| 浪高 Hs | 涌的能量，决定整体音量和低频 | 用户旋钮 / 海洋 API |
| 周期 Tp | 两次拍岸的平均间隔（4 到 20 秒），带随机抖动 | 用户旋钮 / 海洋 API |
| 浪组 | 真实的海是"七浪一组"，大小有起伏 | 引擎内置 |
| 拍岸力度 | 拍击瞬态的强度和长度 | 用户旋钮 |
| 冲滩 | 水推上沙滩的距离和回退的长度 | 用户旋钮，受坡度影响 |
| 距离 | 听者离浪线多远（低通 + 近场层衰减） | 用户旋钮 |
| 材质 | 沙滩 / 卵石滩 / 礁石 | 用户选择 / 地理数据 |
| 风 | 风声床和风对高频的调制 | 用户旋钮 / 气象 API |
| 生物 | 海鸥密度，后续加燕鸥、海燕、远处的船 | 用户旋钮 / 时间和季节 |
| 种子 seed | 同一个种子生成同一片海，视频人需要"再来一次一样的" | 用户输入 |

### 2.2 v0（本仓库现在的 `index.html`）

- 纯浏览器、单文件、零依赖、离线可用。
- 上面所有参数都有旋钮，材质三选一，几个预设。
- **拍一浪**：按空格立刻来一浪。这是给视频人的杀手功能的雏形：画面里浪打上来的那一刻，按一下。
- **叫一声海鸥**：同理，画面里鸟起飞的时候按一下。
- **导出 WAV**：用 OfflineAudioContext 离线渲染任意秒数，直接下载丢进剪映 / CapCut / Premiere。
- 种子可复现。

### 2.3 v1：给创作者的 Web App

- 时间轴：把"拍一浪"和"叫一声海鸥"变成可编辑的事件，能对着视频预览打点。
- 导出分轨 stems（远涌、近浪、泡沫、鸟、风各一轨），混音师才用得上。
- 无缝循环导出（指定时长，头尾交叉淡化）。
- 响度归一（视频平台的 LUFS 标准）。
- 分享链接 = 参数 + 种子，一个 URL 就是一片海。

### 2.4 v2：真实海滩（方向 C）

- Open-Meteo Marine API 免费给全球任意经纬度的浪高、浪周期、浪向、风；NOAA 浮标数据可做校准。
- 用户定位或搜索海滩 → 拉此刻海况 → 映射成引擎参数 → "现在那片海的声音"。
- 材质来自 OpenStreetMap 的海岸线标签（sand / pebbles / rock）。
- 时间和季节决定鸟类和昼夜差异（夜里没海鸥，只剩浪和风）。

### 2.5 v3：硬件（方向 E）

- 先用 Web 版把参数模型和 DSP 打磨到满意，再移植。
- 平台候选：Daisy Seed（Cortex-M7，专为音频，C++）、Teensy 4.x、ESP32-S3（便宜但音频质量一般）。
- 形态候选：桌面小盒子（3 个旋钮：浪、距离、风，一个按钮"拍一浪"）；Eurorack 模块（CV 输入
  拍岸触发，浪高由 CV 调制，这个玩家群愿意花钱）。
- 方向 D 的植物传感器（两片电极 + 电阻测量）在硬件版上是天然的扩展口。

## 3. 你目前 miss 掉的部分

按重要程度排。

1. **最大的假设还没验证**：合成能不能"以假乱真"。做 10 个人的盲听 A/B（合成 vs 真实录音 vs 白噪音 app），
   这一周就该做，比任何功能都优先。`index.html` 就是为了这个。
2. **视频人的真正痛点不是"海浪声"，是"对拍"**。采样库里海浪有几千段，缺的是"浪在第 3.2 秒拍上来，
   海鸥在第 5 秒叫"。这是合成才能给的，也是你从抖音那次经历里真正感受到的东西。
   产品定位应该是"能对画面演奏的海"，而不是"又一个白噪音"。
3. **材质比浪高重要**。沙滩是嘶声，卵石滩（英国 Brighton 那种）是哗啦啦的滚动声，礁石是低频的轰和溅。
   用户脑子里的"海"是具体的一片海，材质决定他认不认得出来。
4. **循环感是白噪音 app 的死穴**，也是你的护城河。程序化生成永远不重复，宣传语一句话就够："这片海不循环。"
5. **版权与授权**：用真实采样要处理 license；程序化输出没有这个问题，对广告和商用视频是实打实的卖点。
   如果后面引入颗粒合成的采样，采样必须自己录或用 CC0。
6. **命名**：Wavemaker 是一个已有多年的低代码平台的商标，App Store 也有同名。上线前换名。
7. **位置隐私**：方向 C 用定位，要明确只在设备端用，或者只让用户手选海滩。
8. **心理声学**：睡眠场景下低频要收敛、拍岸瞬态要压平；创作场景下相反。同一个引擎，两套"口味"预设。
9. **响度与格式**：视频平台有响度规范，导出要有 LUFS 归一；导出格式要有 48kHz WAV，不只是 44.1k。
10. **植物电信号是调制源，不是声源**。PlantWave 那类设备本质是测皮肤电导的慢变随机信号，直接出声很难听；
    但用它来调制"下一浪什么时候来、多大"，就是一件有诗意的事。
11. **硬件要提前决定 DSP 语言**。Web Audio 的图结构在单片机上没有，最终要手写 C++ 滤波器和包络。
    所以引擎设计从现在起要保持"纯数学可移植"，不要依赖只有浏览器才有的节点。
12. **意义问题**：你说"有时候只有你自己找到了它的意义"，我同意，但补一句：工具的意义来自一个具体的人的
    具体一次使用。先服务那个人：剪抖音的你，需要 15 秒、强度可调、免版权、和画面对拍的海浪声。
    把这一件事做到极致，其他方向会自己长出来。

## 4. 补充的部分：可以顺手加的东西

- **海边之外**：同一套引擎的参数模型换一组滤波器和包络，就是河流、雨、火、风穿过树林。
  引擎的名字如果叫"自然声场引擎"，海浪只是第一个乐器。
- **鸟不止海鸥**：燕鸥（尖而短）、海燕、鸬鹚，以及远处的船笛和浮标铃，都是很便宜的加分项。
- **昼夜**：夜里的海更低沉、鸟停了、风变清晰。一个"时间"旋钮就能做。
- **"去海边"按钮**：你说鼓励用户真的去海边。可以在 v2 里做成：显示离用户最近的海滩、此刻海况、
  和一句"现在的海比 app 里的好听"。这是产品的态度，也是差异点。
- **社区海**：用户上传"我家的海"的参数和种子，形成一个海滩地图。

## 7. 第二次发散：仙女棒和蒲公英，以及它们为什么不脱离中心

这两个想法看起来离海很远，其实和海浪是同一个东西，它们把引擎的名字定了下来。

### 7.1 统一模型：颗粒

| 现象 | 颗粒是什么 | 一颗颗粒的声音 | 颗粒怎么来 |
|---|---|---|---|
| 海浪回退时的卵石滩 | 一颗石头翻滚 | 3 kHz 附近的短噪声脉冲 | 回退期间密度先升后降 |
| 海浪的泡沫 | 一个气泡破裂 | 极短的高频嘶声 | 冲滩后密集，然后稀疏 |
| 仙女棒 | 一粒铁屑燃烧 | 5 到 9 kHz 的短噪声，偶尔一个"啪" | 强度随燃烧曲线变化，抱团成不规则律动 |
| 蒲公英 | 一颗种子 | 五声音阶上的一个音 | 一口气吹出来，落地生根 |
| 雨 | 一滴 | 材质决定：叶子、水面、铁皮 | 密度就是雨量 |
| 篝火 | 一次爆裂 | 低频的噼啪 | 和仙女棒同构，只是慢 |

数学上它们都是**强度随时间变化的泊松过程**：每秒有多少颗粒，每颗颗粒长什么样，强度怎么随时间起伏。
海浪那页的卵石层和仙女棒那页的火花，用的是同一段代码结构，只是参数不同。

所以引擎的核心原语有两个：
1. **层**：一个噪声源过几个滤波器，由包络驱动。海浪的涌、拍岸、冲滩、风都是层。
2. **颗粒流**：一个随时间变化的随机过程，往声音里撒颗粒。卵石、泡沫、火花、种子、雨、篝火都是颗粒流。

有了这两个原语，"自然声场引擎"不再是一句口号，而是一个可以一个个往里加乐器的框架。
硬件版也只需要在 C++ 里实现这两个原语。

### 7.2 仙女棒（`sparkler.html`）

- 密度、律动、力度、深浅四个旋钮，正好对应你说的"密度、快慢、力度深浅、节奏律动"。
- **律动**的实现：把泊松过程的强度切成一段段随机长度的片段，每段乘一个随机倍率（有的几乎空拍，
  有的密三倍）。律动越高，倍率越极端，空拍越长，就有了不规则附点的感觉。
- 每根仙女棒有自己的燃烧曲线：点燃时一声"呲"，中段微微起伏，最后 20% 越来越弱、越来越断续，
  律动会自己变强。这是真实仙女棒最有记忆点的部分。
- 可以同时点好几根，每根在立体声里有自己的位置。像一群小孩在院子里。
- 导出一根烧完的全过程，直接就是一段可用的音效。

### 7.3 蒲公英（`dandelion.html`）

蒲公英本身几乎没有声音，所以它不是一个"音效"，而是一个**交互和生成规则**：

- 吹一口气（对着麦克风吹，或按住按钮），种子按迎风面顺序飞走，每颗飞走是五声音阶上的一个音。
- 种子随风漂，落地生根，落地是一个低八度的音。大约十秒后长成一株新的，长成时是一个慢慢涨起来的和音。
- 新的一株也可以吹。整个画面是一个会自己生长的生成式乐器，怎么吹都不会难听。
- 有一个带反馈的延迟给所有的音加了一点尾巴，这就是你说的"有记忆回忆感"的来源。

蒲公英给整个项目带来的东西是：**引擎不只是"发出自然的声音"，也可以"用自然的规则发出声音"。**
一个是模拟，一个是生成。两者共用颗粒流。

### 7.4 关于"脱离中心"

它们没有脱离。海浪、仙女棒、蒲公英的共同点是：
- 都是**很多很小的事件**叠出来的一个整体感觉
- 都不循环，每次不一样
- 都和一段具体的记忆绑在一起（海边、过年、童年的田野）

产品的中心从"海浪"移到了"由颗粒组成的、和记忆绑在一起的自然声音"。海浪只是第一个，也是最难的一个。

| 阶段 | 需要的 | 备注 |

## 9. 第一次校准：为什么第一版像"水泼在热锅上"

你听完第一版说：像水泼到很热的东西上瞬间气化的丝丝声，高频太尖锐，缺少水拍到岸上的那一下。
这个判断被测量证实了。

### 9.1 量出来的问题

`analyze.html` 用同一把尺子量第一版和第二版的引擎输出（各倍频程能量，相对 500 Hz，dB）：

| 倍频程 | 第一版 | 第二版 | 文献目标 |
|---|---|---|---|
| 63 Hz | -6.8 | -8.1 | -8 |
| 125 Hz | -4.4 | -0.8 | -3 |
| 250 Hz | -1.6 | 1.5 | -1 |
| 500 Hz | 0 | 0 | 0 |
| 1 kHz | -0.3 | -3.1 | -3 |
| 2 kHz | +5.1 | -8.0 | -8 |
| 4 kHz | +9.4 | -9.5 | -14 |
| 8 kHz | +8.1 | -15.5 | -21 |
| 16 kHz | -12.5 | -34.9 | -30 |
| 频谱斜率 | **+2.3 dB/倍频程** | -3.4 | -5 到 -6 |
| 频谱质心 | **4274 Hz** | 589 Hz | 几百 Hz |

第一版的能量随频率**上升**，8 kHz 比 500 Hz 还高 8 dB。真实的海是往下掉的。
这就是"热锅"：高频噪声的比例是真实海浪的几百倍（+29 dB）。

### 9.2 原因和改法

| 原因 | 改法 |
|---|---|
| 所有层都用白噪声（每倍频程能量相同） | 改用粉红噪声（每倍频程降 3 dB），只有泡沫、飞溅、卵石保留白噪声 |
| 拍岸是 1.4 kHz 的带通，太"细" | 改成 140 到 1100 Hz 的中低频"轰"，顶上只加很少一点 2 kHz 的飞溅 |
| 冲滩从 1.5 kHz 往上，增益 0.7，是最大的嘶声来源 | 降到 450 到 3800 Hz，增益减到 0.45，音色变亮的幅度也减小 |
| 泡沫增益 0.22 | 减到 0.035 |
| 主低通开得太高 | 随距离从 12 kHz 往下 |

### 9.3 目标曲线从哪来，以及它的局限

`analysis.js` 里的 `TARGET_SURF` 是根据海洋声学文献里海滩录音的典型长期频谱写的：
能量集中在 125 到 1000 Hz，往上每倍频程掉 5 到 6 dB。**它是一个起点，不是真理。**
这次会话的网络策略挡住了所有音频站点，我没能拿到真实录音来验证。

所以下一步是你的：
1. 手机去海边录 1 到 2 分钟（或者从你那条看鸟的视频里直接拖视频文件进去）。
2. 打开 `analyze.html`，拖到 A 区，把报告文字发给我。
3. 我把 `TARGET_SURF` 换成你的海，再调一轮。不同的海滩差别会很大，这正是材质参数存在的理由。

### 9.4 这套方法本身就是产品的一部分

"拖一段真实的海进来，引擎自动校准成那片海"，这是 v2 里"真实海滩"方向的另一条路：
不靠气象 API，靠用户自己的录音。两条路可以并存。

## 10. 仙女棒的第二轮：原味、电子、鼓机

你听完第一版仙女棒说：像被拉长的鞭炮，开头有点激光感，很像 trap 里很快的闭镲滚奏，带一点合成器的味道。
三个感觉指向同一个原因。

### 10.1 第一版为什么不像

| 第一版的做法 | 听感 | 真实仙女棒 |
|---|---|---|
| 每颗火花 = 一个 Q 值 3 的带通滤波器打出来的噪声 | 每颗都是有音高的"叮"，连起来像激光 | 每颗火花极小，没有任何一颗有音高 |
| 每秒一百多颗 | 一颗颗听得出来，像鞭炮 | 每秒几千颗，糊成一片带颗粒感的嘶声 |
| 律动把火花切成一阵一阵 | 像踩镲滚奏 | 中段基本是稳定的，只有快熄灭时才断续 |

量出来的差别：第一版（现在叫"电子"）的包络峰均比是 12.8，一颗颗的尖峰；原味是 1.33，连续的嘶声。

### 10.2 原味模式的物理模型

- **燃烧噪声**：粉红噪声经高通（约 1 kHz）、一个 6 dB 的峰（3 到 5 kHz）、低通。这是铁屑在氧化剂里燃烧的"嘶"。
- **噼啪包络**：每秒 800 到 4000 个泊松脉冲，每个衰减不到 1 毫秒，叠在一个底上，再乘一个慢慢飘的粗糙度。
  这条包络以音频采样率直接驱动噪声的增益，噪声就有了燃烧的颗粒感。这是整个模式的关键：
  **颗粒不是一颗颗放出来的，而是渲染成一条调制曲线**。密度旋钮控制的是这条曲线的脉冲率。
- **飞出去的一颗**：每秒几颗，低 Q，中心频率从 5 到 8 kHz 往下滑，很轻。
- **划着**：一小声往上扫的"呲"。
- **熄灭**：最后 22% 用门控把燃烧噪声切成越来越短的段、越来越长的空，中间飞出最后几颗。

### 10.3 三种口味都保留

| 口味 | 是什么 | 用在哪 |
|---|---|---|
| 原味 | 尽量像真的 | 视频配音、过年的记忆 |
| 电子 | 第一版，拉长的鞭炮和激光 | 一种音色，电子音乐里的纹理 |
| 鼓机 | 电子的火花对齐到节拍网格，BPM、细分、摇摆、随机滚奏、拍首重音 | 你听出来的那个 trap 踩镲，现在是一个乐器 |

"做错了的东西是另一个乐器"，这是这一轮最重要的收获。以后每个引擎都应该保留它的"错误版本"。

### 10.4 从仙女棒发散出去

| 现象 | 和仙女棒的关系 | 实现难度 |
|---|---|---|
| 一挂鞭炮 | 你说"拉长的鞭炮"：电子口味的"啪"放大、密度从低到高再到底、最后一两个落单的 | 低，基本是参数 |
| 烟花 | 升空的哨（往上滑的音）、炸开的"轰"（棕色噪声的一次爆发）、然后一片噼啪（原味的噼啪包络，密度递减）| 中 |
| 篝火 | 原味的噼啪包络放慢一百倍，加低频的呼吸 | 低 |
| 雨打在不同东西上 | 噼啪包络 + 材质滤波器 | 低 |
| 踩镲和沙锤 | 鼓机口味加 MIDI 导出，火花就是鼓点 | 中 |

### 10.5 对照真实录音

和海浪一样，网络策略挡住了视频网站，原味模式是按物理模型做的，没有对过真实录音。
`analyze.html` 的 B 区现在可以渲染三种口味，"对照目标"选"无"就不会拿海浪的目标来比仙女棒。
